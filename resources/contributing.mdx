## Getting Started

<Steps>
  <Step title="Fork the repository">
    Fork [nmggithub/Kass](https://github.com/nmggithub/Kass) to your GitHub account.
  </Step>
  
  <Step title="Clone your fork">
    ```bash
    git clone https://github.com/YOUR_USERNAME/Kass.git
    cd Kass
    ```
  </Step>
  
  <Step title="Set up development environment">
    Ensure you have the latest version of Xcode and Swift installed:
    
    ```bash
    swift --version
    # Swift version should be 6.2 or later
    ```
  </Step>
  
  <Step title="Build the project">
    ```bash
    swift build
    ```
    
    This will build all modules: `MachCore`, `BSDCore`, `Linking`, `Kass`, etc.
  </Step>
</Steps>

## Project Structure

### Module Organization

Kass is organized into several modules with clear separation of concerns:

<CodeGroup>
```plaintext Module Layout
Sources/
├── Kass/              # Main namespace module
├── Mach/
│   └── Core/          # MachCore module (Mach APIs)
├── BSD/
│   └── Core/          # BSDCore module (BSD APIs)
├── Linking/           # Dynamic linking module
├── KassHelpers/       # Helper utilities
├── KassC/             # C compatibility layer
├── OS/
│   └── Core/          # OSCore module
└── Shellcode/         # Shellcode utilities
```

```swift Dependencies
// Module dependency hierarchy
KassHelpers  // No dependencies
Linking      // No dependencies
KassC        // C headers and compatibility

MachCore     // Depends on: KassHelpers, KassC, Linking
BSDCore      // Depends on: KassHelpers, KassC, Linking, MachCore
OSCore       // Depends on: KassHelpers, KassC, BSDCore, MachCore
Shellcode    // Depends on: KassHelpers, MachCore

Kass         // Namespace: KassHelpers, BSDCore, MachCore
```
</CodeGroup>

### Stability by Module

<AccordionGroup>
  <Accordion title="MachCore - Stable" icon="check">
    - **Status:** Mostly stable
    - **Changes Expected:** Minimal (virtual memory API additions)

    - **Testing:** Critical - this is the most used module

  <Accordion title="BSDCore - In Development" icon="wrench">

## Code Style Guidelines

### Swift Conventions

Kass follows Swift best practices with specific patterns:

<CodeGroup>
```swift Namespacing
// Use nested types for organization
extension Mach {
    public class Task: Mach.Port {
        // Task implementation
    }
}

extension Mach {
    public struct VMFlags: OptionSet {
        // Flags implementation
    }
}
```

```swift Error Handling
// All fallible operations throw
public func suspend() throws {
    try Mach.call(task_suspend(self.name))
}

// Use Mach.call wrapper for kernel calls
try Mach.call(kernelReturnValue)
```

```swift Documentation
/// Brief description of the function.
///
/// Longer description if needed.
///
/// - Parameter param: Description of parameter
/// - Returns: Description of return value
/// - Throws: Description of errors that can be thrown
/// - Important: Critical information
/// - Warning: Important warnings
/// - Note: Additional notes
public func example(param: String) throws -> Int {
    // Implementation
}
```

```swift Type Safety
// Use option sets for flags
public struct PortRights: OptionSet {
    public let rawValue: mach_port_right_t
    
    public static let send = Self(rawValue: MACH_PORT_RIGHT_SEND)
    public static let receive = Self(rawValue: MACH_PORT_RIGHT_RECEIVE)
}

// Use enums for discrete options
public enum HandleType {
    case library
    case symbol
}
```
</CodeGroup>

### Naming Conventions

- **Classes:** Use clear, descriptive names (`Task`, `Port`, `Thread`)
- **Properties:** Use `lowerCamelCase` for properties
- **Functions:** Use verbs for actions (`suspend()`, `resume()`, `allocate()`)
- **Static Properties:** Use for singleton-like access (`.current`, `.Nil`)

### Platform Availability

Mark APIs with appropriate availability attributes:

```swift
@available(macOS 11.3, iOS 14.5, *)
public var isCurrentTask: Bool { 
    mach_task_is_self(self.name) != 0 
}

@available(macOS, deprecated: 12.0, message: "Use safer alternatives")
public func destroy() throws {
    try Mach.call(mach_port_destroy(self.owningTask.name, self.name))
}
```

## Contribution Workflow

<Steps>
  <Step title="Create a feature branch">
    ```bash
    git checkout -b feature/your-feature-name
    # or
    git checkout -b fix/your-bug-fix
    ```
  </Step>
  
  <Step title="Make your changes">
    Write clean, well-documented code following the style guidelines above.
    
    ```swift Example
    extension Mach.Task {
        /// Gets the memory usage of the task.
        ///
        /// - Returns: Memory usage in bytes
        /// - Throws: `MachError` if the operation fails
        public func memoryUsage() throws -> UInt64 {
            // Implementation
        }
    }
    ```
  </Step>
  
  <Step title="Build and test">
    ```bash
    # Build all modules
    swift build
    
    # Run tests if available
    swift test
    
    # Test on your target macOS version
    ```
  </Step>
  
  <Step title="Commit your changes">
    Write clear commit messages:
    
    ```bash
    git add .
    git commit -m "Add memory usage API to Task"
    ```
    
    Good commit message examples:
    - `Add memory usage query to Mach.Task`
    - `Fix port rights enumeration bug`
    - `Update documentation for virtual memory APIs`
    - `Improve error handling in thread creation`
  </Step>
  
  <Step title="Push to your fork">
    ```bash
    git push origin feature/your-feature-name
    ```
  </Step>
  
  <Step title="Open a pull request">
    Go to [github.com/nmggithub/Kass/pulls](https://github.com/nmggithub/Kass/pulls) and open a PR.
    
    Include in your PR description:
    - What problem does this solve?
    - What APIs or behaviors changed?
    - Any breaking changes?
    - Testing performed
  </Step>
</Steps>

## What to Contribute

### High-Value Contributions

<Accordion title="Missing Mach APIs">
  The XNU kernel has many APIs not yet wrapped in Kass. Adding new APIs to `MachCore` is valuable.
  
  **Example areas:**
  - Memory management operations
  - Advanced port operations  
  - Clock and timing APIs
  - Processor and processor set management
</Accordion>

<Accordion title="BSD API Coverage">
  `BSDCore` is in early stages and needs expansion.
  
  **Example areas:**
  - File system operations
  - Process management
  - Network interfaces
  - System call wrappers
</Accordion>

<Accordion title="Documentation & Examples">
  Clear documentation helps everyone.
  
  **Ways to help:**
  - Add code examples to existing APIs
  - Write tutorials for common use cases
  - Improve inline documentation
  - Add safety warnings where appropriate
</Accordion>

<Accordion title="Testing & Compatibility">
  Kass is primarily tested on the latest macOS.
  
  **Testing needs:**
  - Verify deprecated APIs on older macOS
  - Test on different macOS versions
  - Report compatibility issues
  - Add test cases
</Accordion>
