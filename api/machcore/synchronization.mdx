# Synchronization API

The Synchronization API provides Swift-friendly access to Mach synchronization primitives, including eventlinks for low-latency thread synchronization.

## Core Types

### Mach.Eventlink

One side of an eventlink port pair.

```swift
public class Eventlink: Mach.Port
```

Eventlinks provide a low-latency, kernel-mediated synchronization mechanism for coordinating between threads, potentially across process boundaries.

## Creating Eventlinks

### Static Methods

```swift
public static func create(
    task: Mach.Task = Mach.Task.current,
    option: mach_eventlink_create_option_t = .noCopyIn
) throws -> (Eventlink, Eventlink)
```

Creates a new eventlink port pair.

<ParamField path="task" type="Mach.Task" default="Mach.Task.current">
  The task to create the eventlink in (kernel currently only accepts current task)
</ParamField>

<ParamField path="option" type="mach_eventlink_create_option_t" default=".noCopyIn">
  Creation options (`.noCopyIn` is currently the only option the kernel accepts)
</ParamField>

**Returns:** A tuple containing both sides of the eventlink pair.

## Usage Example

```swift
import Mach

// Create an eventlink pair
let (eventlink1, eventlink2) = try Mach.Eventlink.create()

defer {
    try? eventlink1.destroy()
    try? eventlink2.destroy()
}

// Associate threads with the eventlinks
let thread1 = Mach.Thread.current
try eventlink1.associate(
    thread: thread1,
    option: .none
)

// In another thread...
let thread2 = /* get another thread */
try eventlink2.associate(
    thread: thread2,
    option: .none
)

// Thread 1: Wait for signal
Task {
    do {
        let deadline = mach_absolute_time() + 1_000_000_000  // 1 second
        try eventlink1.waitUntil(
            count: 1,
            option: .none,
            clockID: .machAbsoluteTime,
            deadline: deadline
        )
        print("Received signal!")
    } catch {
        print("Wait failed or timed out: \(error)")
    }
}

// Thread 2: Send signal
Task {
    try await Task.sleep(nanoseconds: 100_000_000)  // Wait 100ms
    try eventlink2.signal()
    print("Sent signal!")
}

// Disassociate when done
defer {
    try? eventlink1.disassociate()
    try? eventlink2.disassociate()
}
```

## Advanced Usage

### Bidirectional Synchronization

```swift
import Mach

let (linkA, linkB) = try Mach.Eventlink.create()

// Thread A
Task {
    try linkA.associate(thread: Mach.Thread.current, option: .none)
    
    // Signal and wait for response
    let deadline = mach_absolute_time() + 1_000_000_000
    try linkA.signalWaitUntil(
        count: 1,
        signalCount: 0,
        option: .none,
        deadline: deadline
    )
    print("Thread A: Received acknowledgment")
    
    try linkA.disassociate()
}

// Thread B
Task {
    try linkB.associate(thread: Mach.Thread.current, option: .none)
    
    // Wait for signal then respond
    let deadline = mach_absolute_time() + 1_000_000_000
    try linkB.waitUntil(
        count: 1,
        option: .none,
        deadline: deadline
    )
    print("Thread B: Received signal")
    
    // Send acknowledgment
    try linkB.signal()
    
    try linkB.disassociate()
}
```

### Non-blocking Signal

```swift
let (producer, consumer) = try Mach.Eventlink.create()

// Producer: non-blocking signal
try producer.associate(thread: Mach.Thread.current, option: .none)

// Signal without waiting
try producer.signal()
print("Signal sent, continuing without blocking")

// Consumer: wait with timeout
try consumer.associate(thread: Mach.Thread.current, option: .none)
let deadline = mach_absolute_time() + 500_000_000  // 500ms timeout

do {
    try consumer.waitUntil(
        count: 1,
        option: .none,
        deadline: deadline
    )
    print("Received signal within timeout")
} catch {
    print("Timeout expired")
}
```

## Performance Considerations

Eventlinks are designed for extremely low-latency synchronization:

- **System calls**: Eventlink operations are system calls (traps), not MIG messages
- **Use case**: Best for frequent, low-latency synchronization between threads
- **Cross-process**: Eventlink ports can be sent to other processes for IPC synchronization
- **Lightweight**: Much faster than traditional Mach IPC for simple signaling

## Comparison with Other Primitives

<Expandable title="Eventlinks vs. Semaphores">
Eventlinks are lower-latency than Mach semaphores and are better suited for real-time synchronization scenarios.
</Expandable>

<Expandable title="Eventlinks vs. Mach Messages">
For simple signaling, eventlinks are much faster than sending Mach messages, but they don't carry data.
</Expandable>

<Expandable title="Eventlinks vs. Darwin Threads">
Eventlinks can synchronize across process boundaries, unlike pthread primitives.
</Expandable>
